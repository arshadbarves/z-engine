# v2 rewrite status

Tracks the phases of the v2 rewrite on the `v2` branch. v1 keeps shipping
from `release` until `v2` is merged back at release (phase 10). Since the
cutover (phase 5) the v1 crates are gone from `v2`.

| Phase | Scope | Status |
|---|---|---|
| 0 | Branch, crate skeletons, protocol, llm core types, testkit, prompts skeleton, AGENTS.md v2 section | done |
| 1 | LLM adapters (OpenAI-compatible, Anthropic), retries, fallback, catalog, cost | done |
| 2 | Config v2 + migration, policy engine, host adapters | done |
| 3 | Tools | done |
| 4 | Engine core (single agent) | done |
| 5 | GUI cutover, v1 parity, delete v1 crates | done |
| 6 | Multi-agent orchestration | in progress |
| 7 | MCP v2, LSP tool, memory, repo map, caching | pending |
| 8 | Verification v2 | pending |
| 9 | Commands and extensibility | pending |
| 10 | Hardening, docs, release v2.0.0 | pending |

## Decisions and notes

- Protocol TypeScript is generated by `ts-rs` into
  `crates/z-engine-gui/ui/src/lib/protocol/` via `.cargo/config.toml`.
- `z-engine-tools` depends on `z-engine-policy` for the `Action` type used
  in permission decisions (documented in AGENTS.md).
- Phase 5: the Tauri shell depends only on `z-engine-engine`,
  `z-engine-protocol` and `z-engine-config`. GUI-only queries (session and
  git diffs, worktrees, agent and command catalogs, `@file` search, MCP
  server tests) live in `z-engine-engine/src/engine/queries/`; their result
  types are not re-exported from the engine crate yet, so the shell sends
  them to the webview as JSON.
- Phase 5 leaves for later: MCP tools and LSP inside sessions (phase 7; the
  settings screen can already test a server), prompt and custom slash
  commands (phase 9).
- The deleted v1 crates (`z-engine-core`, `-provider`, `-runtime`,
  `-project`, `crates/legacy/z-engine-context`) remain in git history; their
  design documents are kept with a "Historical (v1)" banner.
