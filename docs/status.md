# v2 rewrite status

Tracks the phases of the v2 rewrite on the `v2` branch. v1 keeps shipping
from `release` until the cutover (phase 5) lands on `v2` and `v2` is merged
back at release (phase 10).

| Phase | Scope | Status |
|---|---|---|
| 0 | Branch, crate skeletons, protocol, llm core types, testkit, prompts skeleton, AGENTS.md v2 section | done |
| 1 | LLM adapters (OpenAI-compatible, Anthropic), retries, fallback, catalog, cost | in progress |
| 2 | Config v2 + migration, policy engine, host adapters | in progress |
| 3 | Tools | pending |
| 4 | Engine core (single agent) | pending |
| 5 | GUI cutover, v1 parity, delete v1 crates | pending |
| 6 | Multi-agent orchestration | pending |
| 7 | MCP v2, LSP tool, memory, repo map, caching | pending |
| 8 | Verification v2 | pending |
| 9 | Commands and extensibility | pending |
| 10 | Hardening, docs, release v2.0.0 | pending |

## Decisions and notes

- The v1 `z-engine-context` crate moved to `crates/legacy/z-engine-context`
  (package `z-engine-context-v1`) so the v2 crate can own the name.
- Protocol TypeScript is generated by `ts-rs` into
  `crates/z-engine-gui/ui/src/lib/protocol/` via `.cargo/config.toml`.
- `z-engine-tools` depends on `z-engine-policy` for the `Action` type used
  in permission decisions (documented in AGENTS.md).
