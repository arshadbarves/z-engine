# Z Engine GUI — UI Guide (Svelte 5)

Status: **canonical** · Frontend is Svelte 5 + Bits UI + Vite, hosted by Tauri 2.
Read this before adding or changing any file under `crates/z-engine-gui/ui`.

This guide exists so humans and LLMs produce the same kind of code: small
files, one responsibility, reusable primitives, no ad-hoc overlays.

## 1. Why this stack

The v0.1 React UI grew a 1 000-line event god-module, hand-rolled popovers /
dialogs / menus, and `useSyncExternalStore` boilerplate in every screen.
That is the clutter this rewrite removes.

| Choice | Why |
|---|---|
| **Svelte 5 (Vite, no SvelteKit)** | Single-window Tauri SPA. Kit routing/SSR adds nothing and fights the webview. |
| **Runes + thin store bind** | Components read reactive values. Domain/runtime stays plain TypeScript so vitest does not need a browser. |
| **Bits UI (headless)** | Accessible Dialog, Menu, Select, Tabs, Combobox, Popover, Tooltip. We own the look. |
| **No Tailwind / no shadcn-svelte** | The look is already defined by our own tokens in `styles/tokens.css`. A second design system would fight it. |
| **Hugeicons (core paths)** | Same icon set as before; rendered by our `Icon` primitive, not a React wrapper. |

Do not add a component library that ships its own theme.

## 2. Dependency direction

```
.svelte screens  →  $lib/ui primitives (Bits UI wrappers)
                 →  $lib/runtime (sessions / catalogs / events)
                 →  $lib/domain  (pure helpers + tests)
                 →  $lib/commands/*.ts (ONLY Tauri invoke)
```

- Screens never call `invoke()` or `@tauri-apps/api/core`.
- Event listening lives in `lib/runtime/listen.ts` only.
- Bits UI is imported only inside `lib/ui/*`. Feature components use our
  wrappers (`Dialog`, `Menu`, `Select`, …).
- The IPC contract in `lib/commands/*.ts` is the seam to the Tauri shell;
  engine events arrive as `EventEnvelope`s on the `engineEvent` channel and
  their types are generated into `lib/protocol/` (never edit those files).

## 4. Patterns

### 4.1 Component shape

```svelte
<script lang="ts">
  import { Button } from "$lib/ui/Button.svelte";
  import { sessions } from "$lib/runtime";

  type Props = { pending?: boolean };
  let { pending = false }: Props = $props();

  const active = $derived(sessions.active);

  function onSend() {
    /* call a function from lib/runtime or lib/commands — no invoke() */
  }
</script>

<section class="composer">
  <Button variant="accent" disabled={pending} onclick={onSend}>Send</Button>
</section>
```

- `$props()` / `$state` / `$derived` / `$effect` only. No Svelte 4 `export let`.
- Props are a typed object. Events that bubble use callback props
  (`onClose`, `onApprove`), not `createEventDispatcher`.
- One visual thing per file. If a file names a card, it renders that card.

### 4.2 Stores

Runtime state is rune classes in `lib/runtime/*.svelte.ts` (`sessions`,
`sessionList`, `catalogs`) whose logic delegates to pure `lib/domain`
reducers, so tests stay node-vitest. The remaining `{ subscribe,
getSnapshot }` stores (toasts, workspaces, updates) are bound in screens:

```ts
const toasts = bindStore(toastStore); // toasts.current
```

App chrome state (palette open, settings open, sidebar) lives in
`lib/stores/ui.svelte.ts` as runes — it is UI-only and is not unit-tested
through the event loop.

Never put Tauri listeners or `invoke` inside a store except `listen.ts`,
`lib/commands/*.ts`, and the workspace/update stores that already wrap a single
command.

### 4.3 Bits UI — use the kit, not the package

```svelte
<!-- YES -->
<Dialog.Root bind:open>
  <Dialog.Content title="Worktree">…</Dialog.Content>
</Dialog.Root>

<!-- NO — do not import bits-ui from a feature component -->
<script>
  import { Dialog } from "bits-ui";
</script>
```

Wrappers apply our tokens (`--surface`, `--radius-m`, `--shadow-floating`)
and the existing class names (`.dialog`, `.menu`, `.select`, …). When Bits
UI’s API moves, only `lib/ui/` changes.

Use Bits primitives for:

| Need | Kit |
|---|---|
| Modal / settings / worktree | `Dialog` |
| Confirm destructive | `Dialog` (alert variant) |
| Context menu, overflow | `Menu` |
| Mode / model / effort | `Select` |
| Settings sections | `Tabs` |
| ⌘K palette, @file, slash | `Combobox` |
| Composer extras | `Popover` |
| Icon button labels and their shortcuts | `Tooltip` (`text`, optional `shortcut`) |

Do not invent another `position: fixed` overlay with a backdrop `div`
unless Bits has no primitive for it (the boot splash is the exception).

### 4.4 Chat surfaces

- The transcript renders turns reduced by `lib/domain/sessionView` and
  `lib/domain/timeline`: user cards, streamed assistant text with a
  thinking disclosure, tool calls as `components/chat/tools/*` cards, and a
  turn footer with usage, cost and the verification badge
  (`Verified` / `Unverified` / `Failed` / `NotApplicable`, with check evidence).
- Approvals appear inline as `ApprovalCard`s (allow once / for the session /
  for the project, or deny with feedback); questions and plan reviews use
  `components/planning/`. Subagent approvals are labelled with their agent.
- The composer handles `@` file and agent mentions, `/` commands (engine and
  app commands), `!cmd` shell, `#note` memory, image attachments, and a
  steering queue while a turn runs. Rewind is on each user message.
- The work panel (`components/agents/`) lists subagents and background jobs;
  the diff overlay has session and git scopes; the Now card and the
  prompt inspector read the engine's context breakdown and last request.

### 4.4.1 One home per fact, the companion and the status line

Each piece of information has exactly one place in the UI. A summary may
link to its own detail, and the ⌘K palette and shortcuts may repeat any
action, but two views never show the same fact. The title bar naming the
open chat (as a window title does) is the one deliberate exception to the
sidebar's list.

- **Live status lives in the title bar's status line** (`components/chrome/TitleStatus.svelte`).
  Its state comes from the pure `liveStatus()` in `lib/domain/liveStatus.ts`,
  highest priority first: this chat needs you, a passing notice, provider
  retry, work in progress, a turn that just ended, the away recap, idle;
  another waiting chat is reported beside it. Activity text comes from
  `activityLabel()` (plain words: "Reading auth.rs"), recent warnings and
  errors from `recentActivity()`. Add a state there, with a test, rather
  than a new pill or banner.
- **The companion** (`Companion.svelte`) carries the same state as body
  language. Its pose is the pure `companionPose()` in `lib/domain/companion.ts`,
  from the live status and the user's signals (`lib/stores/userSignals.svelte.ts`,
  DOM events only). It is decorative: never the only carrier of meaning,
  never interrupting, still under Reduce Motion, and it honours
  `ui.companion` (lively, calm, off).
- Details live in the Now card (`NowCard.svelte`, on the kit `Popover`).
- Toasts go through the status line (`pushToast` in `lib/runtime/toasts.ts`),
  so push one only for something the user cannot see: a background event or
  an error that is not shown inline. Confirm visible actions at the control.
- Sidebar rows carry at most one mark from `sidebarMark()`; the open chat
  shows none, because the title bar reports it.
- Controls that live in the sidebar (New chat, Search) appear in the title
  bar only while the sidebar is hidden.
- Keep percentage values out of `min-width` inside the status line: they
  skew its intrinsic width and truncate text that would fit.

### 4.5 CSS and visual hierarchy

- `styles/tokens.css` defines every color, material, radius, spacing, type
  and layout token; `base.css` the reset; `motion.css` easing, springs and
  shared keyframes; `materials.css` `.glass`, `.glass-strong`, `.sheet` and
  the scroll-edge fades. Each migrated area has one file there (`shell`,
  `sidebar`, `companion`, `title-status`, `popovers`), each under 400 lines.
- The root stylesheets (`index.css`, `chrome.css`, `settings.css`, …) are
  legacy. When you move an area into `styles/`, delete its old rules in the
  same change; never restyle an area in both places. The legacy token names
  at the bottom of `tokens.css` (`--surface`, `--text-2`, …) exist only for
  those files; new rules use the new names (`--raised`, `--label-2`, …).
- Content is solid, chrome is glass: only surfaces that float above content
  (the Now card, popovers, tooltips, and later the composer) use the glass
  tokens. Transcript text always sits on the solid `--sheet`.
- Keep the hierarchy low-clutter: window material → content sheet → content
  column → quiet nested metadata. Prefer spacing and type weight before
  adding another border, badge, or filled panel.
- Colors come only from tokens, and color means status: `--green`,
  `--amber` (needs you), `--red`, `--blue`, with `-soft`/`-ring` variants.
  Keep transcript and composer aligned with `--measure-chat`,
  `--gutter-chat`, and `--column-chat`.
- Motion: `blurFade` from `lib/ui/motion.ts` for things that appear,
  `Spring` with the `SPRING` presets for size changes, `blur-in` keyframes
  in CSS. Every animation must degrade under Reduce Motion (motion.ts only
  fades; `motion.css` shortens CSS animations).
- Scoped `<style>` in a component is allowed for one-off layout that will
  never be reused. Shared look belongs in that area's stylesheet.
- No inline style objects except chart/canvas geometry.

### 4.6 Icons

```svelte
<script>
  import { Icon, Plus } from "$lib/ui/icons";
</script>
<Icon icon={Plus} size={16} />
```

Add a new icon in `lib/ui/icons.ts` only. Do not import
`@hugeicons/core-free-icons` from a screen.

### 4.7 Full-screen overlay screens (Settings, Prompt Inspector, full-window views)

Full-window overlays must match the home screen's stage + floating island container architecture:

1. **Stage & Window Layout**:
   - Outer stage with smooth `sheet-in` / `sheet-out` transitions.
   - Draggable title bar (`.app-titlebar` with `.titlebar-side` groups) and `data-tauri-drag-region`.
   - macOS traffic lights clearance comes from `html.plat-mac .app-titlebar`.
   - Back button on top-left (`<button class="icon-btn" title="Back (Esc)" onclick={onClose}><Icon icon={ChevronLeft} size={15} /></button>`).
   - Breadcrumbs (`Root / ActiveSection`).
   - Right-side `<WindowControlsMaybe />` for Windows/Linux.

2. **Floating Islands**:
   - Body has `padding: 0 6px 6px 6px` and `gap: 6px` (identical to `.app-body`).
   - Left Navigation Island (`.settings-nav-island`): `background: var(--bg-sidebar); border: 1px solid var(--border); border-radius: var(--radius-m); box-shadow: 0 4px 20px rgba(0, 0, 0, 0.25);`.
   - Right Canvas Island (`.settings-canvas-pane`): `background: var(--bg); border: 1px solid var(--border); border-radius: var(--radius-m); box-shadow: 0 4px 20px rgba(0, 0, 0, 0.25);`.
   - Top of canvas has a 46px header bar (`.settings-pane-head`) matching `.chat-head`.
   - Content body is centered with `max-width: 720px` (or `920px` for wide inspector/diff views).

3. **Navigation & Shortcuts**:
   - Do not display explicit `<kbd>Esc</kbd>` close badges.
   - Always bind a keyboard `keydown` listener for `Escape` to trigger `onClose()`.
   - Never create flat edge-to-edge sheets without the floating container structure.

## 5. How to add things

| Adding… | Do this |
|---|---|
| A screen control | New `components/<area>/<Name>.svelte`. Use kit primitives. Keep ≤300 lines. |
| A Bits wrapper | New file in `lib/ui/`. Re-export from `lib/ui/index.ts`. |
| An IPC command | Rust `src-tauri/src/commands/<domain>.rs` + `generate_handler!` + wrapper in `lib/commands/<domain>.ts`. Then call the wrapper. |
| An engine event | Variant in `z-engine-protocol` (regenerate TS), then reduce it in `lib/domain/sessionView/`. Never listen in a component. |
| A pure helper | `lib/domain/<name>.ts` + sibling `*.test.ts`. |
| A CSS token | `--name` in `index.css`. Use it; do not hard-code hex in components. |

## 6. Testing

- Domain + runtime: vitest, node environment, next to the file
  (`sessionView/reduce.test.ts`, `runtime/sessions.test.ts`).
- Do not mount Svelte in unit tests unless the logic cannot be extracted.
- `npm test`, `npm run check` and `npm run lint` must stay green.
  `npm run build` is the Tauri frontend compile.

## 7. What not to do

- Do not reintroduce React, `useSyncExternalStore`, or `.tsx`.
- Do not add SvelteKit, Tailwind, shadcn-svelte, or Melt UI.
- Do not grow `App.svelte` past wiring (stores → screens). Put handlers in
  `lib/stores/app-actions.ts` or the relevant domain module.
- Do not call `listen("engineEvent")` a second time. `initEvents()` is
  one-shot by design.
- Do not copy-paste a dialog/menu/select. Extend the kit.
- Do not put prompt text, Rust types, or provider IDs in the UI. The
  frontend is presentation-only.

## 9. Visual language (do not restyle casually)

- Dark first. The window material (macOS vibrancy, Windows 11 Mica) shows
  through the title zone, sidebar and gaps; `html.native-glass` is set only
  when the Tauri shell reports the material applied (`app_info.nativeGlass`),
  and `html.solid-surfaces` otherwise, which turns every glass token solid.
- One raised surface: the `--sheet` content sheet (radius 16). The companion
  and status line are the only live element in the title bar.
- SF Pro at 13px (`--text-m`), labels `--label` / `-2` / `-3`; the accent is
  monochrome; color is reserved for status.
- Radius 6 / 8 / 12 / 16 / 22 and full. Hairline separators at 8–14% white.
- Overlay title bar; macOS traffic lights stay system-drawn.

Changing the palette is a design change, not a drive-by cleanup.
